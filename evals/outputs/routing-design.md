# 研究定位、最小判别设计与技能路由

## 范围与依据

仅使用题干的虚构教学材料与项目规则；没有进行真实文献新颖性认证、联网检索、实验或投稿 gate，也没有修改项目文件。A 使用 `paper-positioning`；B 依据 `paper-harness` 和对应技能说明做路由判断，另由一个只读子代理独立核对。五项是假设请求的分类，本次不实际执行它们。

规则依据：[AGENTS.md](../../AGENTS.md)、[ACADEMIC_WRITING.md](../../ACADEMIC_WRITING.md)、[RESEARCH_HARNESS.md](../../RESEARCH_HARNESS.md)，以及 `.agents/skills/` 下相应 `SKILL.md`。

## A. 当前定位

**目前不能把“只核对上一步动作影响的字段”称为新机制，也不应写 “first state verification framework”。** 在本题给定的比较范围内，L1 已经包含同一策略并评价了模拟订单成功率；给同一操作规则换名称没有产生机制差异。这足以否定当前“首次”的论证，但不是搜索真实文献后得出的全球新颖性结论。

| 已有材料 | 当前证据状态与边界 |
| --- | --- |
| L1 的虚构摘要 | 题干称其已有策略与模拟评价；没有原文、实现和实验细节，不能据此认定它未研究延迟或部分写入失败。 |
| 你的接口草图 | 属于提案；接口设计不能证明核对逻辑已经可运行，更不能证明性能改善。不能把它登记为 `measured` 或 `verified`，也不能仅凭接口把完整策略登记为 `implemented`。 |
| 可取得的模拟环境 | 提供潜在测试条件；尚需明确延迟语义、读可见性、故障与恢复规则及成功判据。 |

**适合继续的定位是：既有策略在延迟和部分写入条件下的适用边界与质量—读取开销研究。** 当前判断为“机制与已知材料重合；新的评价候选需要具体前置条件”。若以后确认 L1 已覆盖相同问题、条件和判据，应定位为复现/工程验证，或放弃该候选；不能把摘要未提及当作未被研究的证据。

### 一个具体、可被否定的研究问题

> 在会先确认受理、后更新状态，并可能发生部分写入失败的模拟订单任务中，固定模型、任务、在线状态权限、总调用上限、截止时间和恢复规则后，按最近动作声明的影响字段核对，相对核对全部在线可见任务状态，能否将最终任务成功率的损失控制在 **5 个百分点以内**，同时把每个已分配任务的累计状态读取量降低 **至少 20%**？

这两个数是具体的**先导评价决策门槛**，不是已有数据或通用标准；可在查看评价结果之前按用途改定，不能事后改门槛来宣布成功。

- **成功率 (S)：** 截止时间内满足全部订单目标与必要状态约束的任务数 / 全部已分配任务数。失败、部分完成、超时和缺少有效结果都留在分母。
- **读取量 (C)：** 每个已分配任务中，状态读取 API 实际返回的累计字节数，包括复读及恢复后核对。API 若每次都返回全量状态，本地只看几个字段不能算减少该读取量。
- **辅助结果：** 宣告完成但客观终态不成功的比例、宣告时目标尚未满足的比例、实际调用/重试、tokens 与端到端耗时。提前宣告和最终失败分开；少读字节不自动意味着更快或更便宜。

令 T 为局部核对，F 为全状态核对，假设为 (S_T-S_F\geq-0.05) 且 (C_T/C_F\leq0.80)。它评价一个有限环境中的权衡，不预设正结果。

关键可判别点是：**最后一步的局部后条件成立，是否足以说明整个订单已完成？** 一个待检查的假设场景是退款字段已经更新，但此前库存释放仍未完成；它不是已观察失败。反之，若动作严格串行、读一致性足够、影响字段完整覆盖后条件，且已确认状态不会再被在途动作改变，延迟和部分写入本身未必使 T 失效。失败发生在 T 已覆盖的字段中时，T 也可能正确捕获，不能把“注入故障”当作已有机制差异。

工作标题可用 **“Evaluating Action-Local State Verification under Delayed and Partial Tool Updates”**，不加 “first”，也不暗示已有结果。

### 最小有判别力的设计

**第一步：核对接口契约。** 明确受理、写入、读可见和最终完成/失败的时点。同步工具只是晚返回，不一定具备本问题需要的异步交错。影响字段 (F(a)) 必须在故障发生前由工具契约或实际可得信息定义，不能从模拟器真值事后挑字段。确认字段投影能改变真实读取量；否则当前成本假设直接失去依据。成功由行动策略之外的订单目标与终态判据决定，模拟器真值仅用于离线评分，不回流在线动作或重试。当前尚缺这些接口细节和可运行的两种策略，不能记录为实验已完成。

**第二步：用同一最小订单流程设计四条边界轨迹。** 一个动作至少涉及两个字段，完整任务目标预先固定。

| 条件 | 最小判别目的 |
| --- | --- |
| 无异步延迟、完整写入 | 检查两组能完成健康任务，评分器认可正确终态。 |
| 有异步延迟、最终完整写入 | 区分尚未提交与永久失败，等待进入时间预算。 |
| 无异步延迟、部分写入失败 | 检查 T 能否识别其字段集合内未满足的后条件。 |
| 有异步延迟、部分写入失败 | 若接口允许，让前一步必要状态在最后一步局部字段通过时仍未满足，观察 T/F 判断及恢复的差异。 |

四条轨迹用于检查逻辑、实现与评分，不是总体成功率的四个统计样本。若第四条在真实接口语义下不可能发生，记录阻止它发生的约束，不偷偷改环境制造区别。

**第三步：主评价只需 T/F 两臂。** T 按预声明 (F(a)) 核对；F 从相同在线状态源检查完整任务相关状态及约束，不能额外读取 oracle。T 同时代表当前提案与对 L1 摘要策略的操作化重建；没有 L1 细节，不能称忠实复现。不要把两个行为相同的版本当成两个新旧机制臂。

两臂使用隔离环境副本、相同初态与预生成故障安排。固定非核对提示、模型、总预算、截止时间和允许的恢复规则；所有读写、核对、等待和重试计入对应预算，并报告实际消耗。故障按动作语义/操作标识绑定，避免多一次调用意外改变另一组的故障难度。读取字段范围是本次干预，信息来源权限保持一致。

这个主问题无需默认增加“不检查”臂。只有要进一步声称“检查本身有效”才需相同总预算的不检查基线；若新策略还改变等待或重试，就补相同等待/重试规则的对照。否则收益可能来自这些变化。

**建议给先导评价设一个上限：** 技术检查通过后，在“异步延迟 + 部分写入失败”主条件使用预先生成的 **60 个独立任务及故障安排，进行 T/F 配对评价**。探索调参使用另外的材料。这个数量与 5 个百分点门槛关联：若没有一次“F 成功而 T 失败”，该退化概率的一侧 95% 二项上界为 (1-0.05^{1/60}\approx4.87\%)，可作为成功损失的保守筛选证据。它不是通用种子数，也不保证成本估计精度或跨任务族泛化；相关模板重复不能冒充独立样本，两组共同失败也不能当成策略有用。

至少记录任务/模板 ID、初态与目标、故障安排、模型和提示版本、动作及时间、(F(a))、返回状态/字节数、核对结论、恢复分支、预算、终态和独立标签。报告配对成功差、读取量比值与适合真实独立单位的不确定性；复读次数不能充作独立样本。

### 停止与继续条件

| 条件 | 决定 |
| --- | --- |
| 只有同一策略与新名称 | **现在就撤回新机制/first 定位**；无需等实验。 |
| 缺异步语义、字段投影、有效实现或独立评分 | 暂停对应性能评价，列明具体前置条件；不扩成大框架。 |
| 一个有效反例表明局部通过而完整目标未满足 | 撤回“局部核对普遍保证完成”的主张。该反例不单独给出平均失败率，也未必否定允许 5 个百分点损失的有限假设。 |
| 成功差的一侧下界至少为 −5 个百分点，读取量比值的一侧上界不高于 0.80 | 可进入更大、独立的确认评价；仅报告该条件与精度内的支持。 |
| 相应区间表明成功损失超过 5 个百分点，或读取量下降不足 20% | 当前联合假设被反驳；保留负结果和代价，不替换主指标。 |
| 到 60 个独立配对实例时，区间仍跨门槛 | 结论为**不确定**，停止这一轮；不一直追加样本直到显著。若继续，应说明精度缺口并另立确认设计。 |
| 策略开关未生效、评分器失灵、故障失衡或两组没有有效成功轨迹 | 定位为实现/测试缺乏判别力，不能当作假设成立或失败。 |

当前下一步是“动作—字段—提交时点—成功谓词”的最小接口契约与边界场景实现。本报告提供设计，未执行它们。

## B. 五个请求的最小路由

这里的“全流程”指项目级审稿、修复、证据/数值/引用核查和投稿闭环，不意味着每次从选题重新开始。

| 请求 | 最小技能与必要后续 | 交付物 | 是否需全流程 |
| --- | --- | --- | --- |
| ① 只修这句英语的语法 | **`paper-voice`**；语法修改和一次局部保真核对。 | 修正后的英文句子；只要改文就只交改文。妨碍忠实修改的具体矛盾才另给最小说明。 | **否。** 不建账本、不做全稿审查或新实验；保留提供的事实不等于认证事实。 |
| ② 根据已给相似度报告修改相关工作 | **`paper-rewrite`**；对照匹配段落、报告和可用来源，重组论证并保留归属。来源对照已属于该技能。 | 修改后的英文相关工作；需要报告分析时附匹配位置、原因、处理与具体来源缺口。 | **否。** 不默认加入 positioning、draft 或全稿 audit。未经同设置实际重测，不声称相似度达到某值。 |
| ③ 找当前稿件的拒稿理由 | **`paper-redteam`**；仅为核验具体问题时加 **`paper-evidence-audit`**。 | 有位置、证据/缺口、后果、类型/严重程度、最小检查和关闭条件的 findings。 | **否。** 可审全文，但交付仍是审稿发现；不擅改稿或运行实验，不预设拒稿或凑问题数。 |
| ④ 按已知审稿意见修稿和回复 | **`paper-revision`**；按实际改动做受影响内容的 **`paper-evidence-audit` / `paper-voice`**。不强制重做 redteam 或加 harness。 | 有证据支持的英文修订稿、符合实际已完成工作的回复信、依赖内容复查、具体未完成证据任务。 | **无需重启全流程，但需完成本次修订闭环。** 直接完成已授权且有依据的修改；审稿人的实验建议本身不是新实验授权。 |
| ⑤ 按项目规则完成投稿前全面检查 | 实际执行时用 **`paper-harness`** 统筹，覆盖必要的 **`paper-redteam` → `paper-revision` → `paper-evidence-audit` → `paper-voice`**。 | 当前版本的检查报告、必要修稿、问题关闭证据、准确记录与版本快照、gate 结果；有实质阻塞则不能标 ready。 | **需要投稿级完整范围。** 从现有状态继续，不机械重跑有效检查；本次只是说明路由，因此不执行。 |

⑤实际执行时必须覆盖项目要求的 `claims`、`numbers`、`citations`、`manuscript_boundary`，核对当前版本并解决实质问题，再运行：

```bash
python3 tools/paper_gate.py check --project . --submission
```

该 gate 检查记录完整性与已查版本的新鲜度，不验证科学结论真假或保证接收。不能删问题、虚填 pass 或只刷新哈希来使其通过。`paper-positioning`、`paper-draft`、`paper-rewrite` 仅在具体修复需要时加入，“全面”不等于遍历全部技能。依据：[RESEARCH_HARNESS.md](../../RESEARCH_HARNESS.md) 第 2、4、8、11 节。

已读取的 [PROJECT.json](../../research/PROJECT.json) 列出上述四项必需检查；[state.json](../../research/state.json) 当前为 `stage: setup`、`submission_requested: false`、`checks: {}`。本次路由说明没有将其改成投稿请求，也没有登记或宣称任何投稿核查通过。
