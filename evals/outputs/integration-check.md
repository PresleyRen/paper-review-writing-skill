# 技能整合复查

日期：2026-10-19。对象：用户要求核实是否整合参考方法、是否有选择与安装说明、是否实际测试。

## 独立只读检查

审查者使用无编写历史的新上下文，读取项目入口、harness、写作规则、方法来源、prompts、八个技能正文与元数据、其本地引用资源及安装器。没有读取既有 VALIDATION.md 或 eval 输出，也没有改动原项目。

实际发现：

- 八个技能均有正文、元数据和被正文引用的本地资源。
- 六种指定任务（仅语法、口述起草、已有意见修订、只审稿、投稿前全流程、相似度改写）的路由在项目规则、harness、prompt 与技能描述中一致。
- 图片方法、反防御性写作和作者样本风格方法都能对应到具体执行步骤；这是选择性整合，不是宣称移植外部资料所有细节。
- 安装器包含八个目录及资源；harness 已说明单独一个技能不等于全套已安装。
- 两处小型衔接问题需要修正：审计参考文档的 simulated/inferred 与项目 evidence_status 枚举容易混用；非交互说明指示修改的材料路径文件与真实 prompt 不一致。

## 本轮完成的修正

1. 审计技能与参考协议明确区分候选 unverified、人工核查结果和 claims.tsv evidence_status。模拟写入条件，未检验的解释单独记录为假设。
2. 非交互说明指向 research/PROJECT.json 的真实材料路径；仅有特殊任务范围才编辑 review_only.txt。
3. 首次安装 prompt 改为完整套件路径和目标项目路径，不要求新环境已经识别 paper-harness。
4. 新增 SKILL_GUIDE.md，列明整套安装、技能选择、17组 prompt 对照、方法整合位置和依赖。安装器复制该指南。
5. 新增安装后核验 prompt，要求分别报告文件完整性、客户端可见性和实际任务表现。
6. 已安装 harness 中关于 VALIDATION.md 与 examples 的说明明确指向套件源目录，避免把默认未复制的开发评估文件当成本地现有文件。

复查不代表重新逐页检查外部仓库的所有历史版本；原始来源与取舍保留在 METHODS_AND_SOURCES.md。
