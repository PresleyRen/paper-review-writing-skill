# 对 review-case 的严格审稿报告

## 总体判断

**按当前提交材料，建议拒绝以现有核心结论接收。** 最先需要回答的不是如何解释“22.9 个百分点”的提升，而是这个数字为什么把两种分母放进同一比较。其次，题目和方法承诺预算匹配，记录却给出 4 与 16 的调用上限；正文宣称跨种子稳定，实际只有一个已完成种子；检查器声称不依赖特权状态，记录却明确写着读取 `simulator.ground_truth`。这些问题直接影响比较的有效性和结论的真实性，不能靠补一段 limitations 解决。

在暂时接受记录中的成功标签正确这一前提下，现有材料支持的观察是：**种子 7 中，两组各分配 100 个任务，基线记录 66 次成功，协调器记录 80 次成功；按预定口径，相差 14.0 个百分点。两组记录的模型调用上限不同。** 材料尚不能把这一观察归因为协作本身、证明推理能力改善，或证明生产可用性。

本次识别出 **9 个可区分的实质问题：4 个已证实问题，5 个证据缺口。** 对这份极短节选，继续凑到 12 条会把同一根因重复计数，或把未查明的风险包装成事实。下文没有把指标分母错误、88.9% 错报和 22.9 个百分点错报拆成三条。

## 逐项拒稿问题与修复要求

### RT-01｜主指标违背定义，结果比较混用分母

**类型 / 严重度：confirmed / blocking。**

**定位与证据：** M 的 Methods，第 7 行，将成功定义为所有已分配任务中完成的比例；R 的 `metric_definition` 又明确要求超时算未成功。C 第 2 行却返回 `successes / (successes + failures)`，完全没有使用传入的 `timeouts`。M 的 Results，第 11 行，报告的协调器 88.9% 恰好对应 `80 / 90`，基线 66.0% 却对应 `66 / 100`；两者没有采用一致口径。

**为何足以影响接收：** 主结果的大小无法由声明的指标复现。按既定定义，协调器应为 80.0%，增益应为 14.0 个百分点。即使统一采用当前函数，也只能得到 73.3% 对 88.9%，而非正文的比较。这不是舍入误差，也不能把正文的计算差异直接解释为某种真实性能增益。现有材料未提供结果表生成流程，因而不能断言错误发生于哪一步，更不能推断作者意图。

**最小核查 / 修复：** 依据现有记录统一重算，把全部已分配任务纳入主分母，并沿结果生成路径检查基线与协调器是否经过同一评分、汇总和格式化步骤。可以另报“未超时任务中的成功率”，但应清楚定义为另一个指标，不能替代原定完成率。

**关闭条件：** 正文、指标实现和可追溯的结果生成记录遵守同一定义；由当前计数得到 66.0%、80.0% 和 14.0 个百分点。修正算术仅关闭指标问题，不会自动解决后面的公平比较与因果归因问题。

### RT-02｜“预算匹配”被记录中的调用上限直接否定

**类型 / 严重度：confirmed / blocking。**

**定位与证据：** M 第 1 行题目为 “Budget-matched multi-agent coordination”，Methods 第 7 行声称模型调用预算相等。R 中 `baseline.max_model_calls = 4`，`coordinator.max_model_calls = 16`，分别位于第 12 行和第 21 行。

**为何足以影响接收：** 这组实验没有兑现主贡献的比较条件。更多允许的调用能够提供额外尝试、检查或恢复机会，构成尚未排除的解释。必须精确区分：**记录证明上限相差四倍，未记录每次实际调用量，因此不能写成“协调器实际花了四倍算力”。** 同样，即便事后发现平均调用量相近，也不能抹去原先提供的预算机会不同。

**最小核查 / 修复：** 先核对配置中该字段的作用域和实际执行时如何限额，再导出任务级调用账本，计入全部工作 Agent、协调、重试及实际存在的模型检查开销。保留“预算匹配”结论需要一个按相同预算规则执行的单 Agent 对照；若当前无法补足，应将这组结果如实定位为不同预算条件下的观察，移除相等预算及相应机制结论。

**关闭条件：** 比较中的可用预算、计数口径与执行证据一致，并提供支持所保留结论的对应结果。仅改题目或承认预算不同，可以关闭错误表述，不能成为预算匹配有效的新证据。

### RT-03｜检查器“不用特权状态”的说法与输入记录矛盾

**类型 / 严重度：confirmed / blocking；在线信息泄漏仍未证实。**

**定位与证据：** M 的 Results，第 11 行，声称检查器不需要特权状态，因而可直接用于生产。R 的 `checker.input` 是 `simulator.ground_truth`，同时 `deployment_tool_exposes_full_state = false`，见第 25 行和第 26 行。

**为何足以影响接收：** 当前检查器使用的状态来源与描述不符，生产接口也未提供该全状态来源。文章把一个尚未建立的输入可得性假设当成了生产适用性的依据。不过，**离线评分器使用模拟器真值可以是合理评测设计；当前记录没有说明真值或检查反馈是否进入 Agent 的在线行动，因此不能据此认定在线作弊或数据泄漏。** 真正已证实的是描述与记录冲突，部署路径没有被建立。

**最小核查 / 修复：** 提供检查器输入构造和调用位置：它是在轨迹结束后离线打分，还是参与行动选择、重试或终止？如果是在线组件，应使用部署时实际可取得的字段重放或复核相关现有轨迹；如果只是离线评分，应如实说明真值仅作评价标签，并给出它不回流到决策的执行路径。

**关闭条件：** 检查器角色、字段来源、可用时点和调用路径均可核查，正文与实际一致。将研究限定为带模拟器真值的设置是一种边界修复；生产可用性的原结论需要另有相应证据。

### RT-04｜“跨种子稳定”把未来计划写成了现有证据

**类型 / 严重度：confirmed / major。**

**定位与证据：** M 的 Results，第 11 行，宣称提升在不同种子上稳定；同一稿件的 Run notes，第 15 行，却说当前表格来自现有一次运行，另外 30 个种子要到下周才跑。R 的两个方法都只有 `seed = 7`，`completed_seeds` 也仅包含 7，`additional_runs_planned = 30`。

**为何足以影响接收：** 稳定性至少涉及已观察到的运行间变化。目前不存在这样的分布。计划进行 30 次实验只证明有计划，无法为正文已经宣称的稳定性背书。现有证据既不能估计跨种子变异，也不能说明种子 7 是否具有代表性。

**最小核查 / 修复：** 现在即可将证据状态更正为一个种子的一次比较。若保留跨种子稳定性，应提交实际完成的全部相关运行、统一汇总规则及运行间差异；不能把失败、超时或不利种子排除出汇总。无需为了文字上的“30”机械要求恰好 30 次，但运行数和分析必须足以支持实际声称的稳定范围。

**关闭条件：** 稳定性措辞由真实已完成的多种子记录支持，或该结论被撤回并准确保留单次观察。计划的运行不得计入已完成样本。

### RT-05｜“相同信息”没有落到可检查的决策输入

**类型 / 严重度：missing-evidence / major。**

**定位与证据：** M 的 Methods，第 7 行，声称两组可以访问相同信息。R 仅给出汇总计数、调用上限和检查器输入；指定目录没有提供两组的提示词、工具权限、检查反馈接收者、状态可见字段或执行轨迹。

**为何足以影响接收：** 即使两组调用预算完全一致，信息条件仍可能不同。多个工作 Agent 的观察如何汇总、基线是否获得同样的工具结果、检查器反馈是否只进入协调器，都会改变这句相等信息声明的含义。目前这些问题没有答案。RT-03 核对的是检查器状态来源；本条核对的是**进入两组行动决策的实际信息是否等价**。不能把共享任务说明直接当作相同信息访问的充分证据。

**最小核查 / 修复：** 给出两组输入与可访问字段的对应表，并以已有调用日志核对信息来源、接收者和时点，特别追踪检查器输出是否影响后续行动。若差异属于方法设计，应明确报告该差异，并增加能隔离该因素的必要对照，或收窄机制归因。

**关闭条件：** 有执行证据支持所声称的信息条件；任何剩余信息差异均被纳入比较定义和结论。当前不能判定差异确实存在，也不能把相等信息视为已经成立。

### RT-06｜任务完成率被当成“推理能力”的直接证明

**类型 / 严重度：missing-evidence / major。**

**定位与证据：** M 的 Results，第 11 行，从整体成功率直接推到“collaboration itself improves reasoning”。C 只计算完成率，R 也只提供成功、失败和超时总数，没有与推理过程或特定错误类型相联系的证据。

**为何足以影响接收：** 服务任务的完成受到尝试次数、执行顺序、工具恢复、停止规则、检查和答案选择等因素影响。现有总分没有区分这些解释，材料也没有展示“协作”在实际路径中改变了哪个因素。即使预算和信息问题都修好了，完成更多任务也仍需论证才能解释为推理能力改善。

**最小核查 / 修复：** 先用既有轨迹明确所主张的协作机制及其预期改变的错误类型，检查额外成功来自何处。若要保留机制结论，应补一个针对该机制、控制其余关键条件的最小比较；例如在相关实现允许时，比对相同资源下独立重复尝试与实际交换信息的协作。仅有若干有利个案不足以证明一般机制。现阶段也可撤回推理与协作本身的因果结论，仅保留条件明确的任务完成率观察。

**关闭条件：** 推理或协作机制有操作定义，并由与之相符的证据和对照支持；或者结论退回实际测得的任务完成率，不再把机制解释写成实验结果。

### RT-07｜成功标签的真实性尚不可审计

**类型 / 严重度：missing-evidence / major。**

**定位与证据：** M 的 Methods，第 7 行，用“completed”描述任务成功；R 的 `successes` 是汇总标签。C 只有比例计算，没有任务成功判定逻辑。指定目录未提供任务目标、终态、成功谓词、判定日志或检查器实现。

**为何足以影响接收：** 修正分母后得到的 66% 和 80%，仍然以成功标签本身有效为前提。`simulator.ground_truth` 只说明一种输入来源，并未说明检查器怎样将该输入映射成“任务完成”。无法判断部分完成、错误终态或无效动作是否被误算为成功。这里没有证据证明这些误标已经发生，问题是主指标的分子尚无法独立复核。

**最小核查 / 修复：** 提供明确的成功谓词和已有任务级终态记录，先核对成功、失败与超时边界样本，再用统一判据对可用记录重评分。验证对象应是任务要求的外部状态或其他客观终止条件，而非 Agent 自称完成。

**关闭条件：** 任务目标、终态、标签和汇总之间有可追溯关系，边界处理明确，复核结果与保留的计数一致或经过有记录的更正。只重算比例不能关闭本条。

### RT-08｜“100 个任务”不足以恢复比较单位、退化情况与不确定性

**类型 / 严重度：missing-evidence / major。**

**定位与证据：** M 的 Methods，第 7 行，仅给出 100 个模拟任务；R 只有每组 `assigned = 100` 和同一个种子，没有任务 ID、任务生成方式、模板结构、配对结果或区间估计。

**为何足以影响接收：** 现有材料不能核对两组是否逐一比较相同任务，也不能判断 100 个任务代表多少独立情境。两个方法拥有相同种子编号，不足以恢复这种设计。即便假定它们确实做了同一批 100 个任务，66 与 80 的边际成功数也可能对应不同的退化图景：数学上既可能是协调器新增解决 14 个且不退化，也可能是新增解决 34 个同时退化 20 个。这里的两种情况只是与汇总数兼容的例子，不是已观察结果。

**最小核查 / 修复：** 导出既有任务 ID、模板或任务族、随机化方式以及两组逐任务标签，说明分析单位与配对关系。然后按实际设计报告差异的不确定性，并检查增益和退化集中在哪里。只有汇总数时，不应擅自套用把所有任务视为独立样本的统计检验。

**关闭条件：** 样本来源、独立单位、配对关系和适合该设计的不确定性可复核；结论范围与真实覆盖一致。增加种子数解决运行波动的一部分，不会自动证明任务多样性或独立性。

### RT-09｜模拟任务结果尚不足以支持“直接适用于生产”

**类型 / 严重度：missing-evidence / major。**

**定位与证据：** M 的 Methods，第 7 行，把评估范围限定为模拟服务任务；Results 第 11 行却声称结果直接适用于生产。除 RT-03 已指出的状态接口限制外，提供的材料没有指定目标生产场景，也没有对应环境的回放或评估证据。

**为何足以影响接收：** 检查器输入能否取得，与模拟结果能否迁移到实际系统，是两个需要分别回答的问题。即使检查器完成部署适配，也仍需说明模拟器覆盖了目标任务的哪些操作条件，以及这些条件是否足以支持所声称的生产范围。当前没有材料让审稿人判断模拟的任务目标、状态更新和失败条件与目标环境之间的关系。这里不能据此断言生产部署必然失败，能够确定的是这一步外推尚未得到支持。

**最小核查 / 修复：** 最小的当前修复是把结论限定在已评估的模拟任务和记录配置。若保留生产结论，先具体限定生产任务与接口，再围绕相关状态可见性、动作结果和失败路径，用可取得的代表性回放或部署等价测试验证关键假设；无需无差别扩充庞大基准，但证据必须对应声称的应用范围。

**关闭条件：** 生产范围和关键假设有对应验证，或撤回该外推并准确保留模拟条件下的观察。部署声明的收窄不等于新增了生产实证。

## 建议的修复顺序

1. **立即清理已证实的记录冲突：RT-01 至 RT-04。** 统一分母，恢复真实数值，说明 4 与 16 是调用上限，区分已完成与计划种子，澄清检查器真值来源与角色。这些工作主要依赖已有材料，不需要先开展新实验。
2. **建立当前结果的可追溯性：RT-05、RT-07、RT-08。** 先取得输入路径、成功判据和任务级记录，确认比较对象、标签及执行条件。若这些基础还不清楚，直接增加几十个种子只会复制同样的解释问题。
3. **决定还要证明哪一个中心命题：RT-02、RT-06、RT-09。** 保留预算匹配、协作机制或生产迁移，就分别需要对应控制或验证；也可以把论文收窄为一个明确标注条件的模拟实验观察。后一种选择修复的是论证范围，并不新增更广结论的证据。

## 不应伪装成拒稿理由的指控

- **没有证据证明数据造假或故意挑选分母。** 可以确认指标与结果不一致，无法由此推断意图。
- **没有证据证明协调器实际用了四倍调用、成本或时间。** 已知的是 `max_model_calls` 上限不同。
- **没有证据证明真值进入在线决策，或只让协调器获得真值。** 检查器输入来源已知，其执行时点和反馈流向未提供。
- **没有证据证明协作无效、所有任务都重复，或生产一定失败。** 目前缺少支持文中强结论的必要证据。
- **不将没有相关工作章节直接判为缺乏创新。** 本次提交的是极短习作节选，未给出待核查的具体文献区分声明，也未提供完整论文供作此判断。

这份提交最有价值的现有事实，是两组标签计数完整且协调器记录的成功数更高。当前可接受的科学处理，是把这条观察从错误指标、不实比较条件与未验证的解释中拆出来，再决定用哪些最小证据支持更强主张。
